# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an accessible, persistent light/dark theme that initially follows the operating system and is verified through visible Chromium E2E testing.

**Architecture:** A React context owns theme selection, persistence, and system-preference synchronization. A reusable toggle is mounted in existing navigation and standalone layouts, while centralized CSS variables and dark palette mappings style the existing application consistently.

**Tech Stack:** React 19, Vite 8, Tailwind CSS 4, Lucide React, Playwright 1.62.

**Spec:** `docs/superpowers/specs/2026-08-19-dark-mode-design.md`

## Global Constraints

- Render exactly `light` or `dark` on `document.documentElement.dataset.theme`.
- Persist only explicit user choices under `najda-theme`.
- Follow `prefers-color-scheme` only while no valid stored choice exists.
- Keep the existing light appearance and brand/emergency colors recognizable.
- The final acceptance run must use headed Chromium.

- [ ] **Step 1: Implement the minimum provider**

```jsx
const STORAGE_KEY = "najda-theme";
const SYSTEM_QUERY = "(prefers-color-scheme: dark)";

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState(readInitialTheme);
  useEffect(() => {
    document.documentElement.dataset.theme = theme;
    document.documentElement.style.colorScheme = theme;
  }, [theme]);
  const toggleTheme = () => setTheme((current) => {
    const next = current === "dark" ? "light" : "dark";
    localStorage.setItem(STORAGE_KEY, next);
    return next;
  });
  return <ThemeContext.Provider value={{ theme, toggleTheme }}>{children}</ThemeContext.Provider>;
}
```
